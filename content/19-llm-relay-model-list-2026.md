# AI 中转站支持哪些模型：2026 年在用的型号 ID 整理

> 搜「中转站模型列表」「API 中转 支持哪些模型」「gpt-6-sol 怎么调用」「claude-opus-5-5 中转」的人，一般不是想看模型评测，是想确认某个 ID 在不在自己那家平台的可选列表里，以及该填进代码里的字符串到底长什么样。这篇只做清单和命名说明。

模型 ID 是接入时最容易出错的一个字符。带不带日期后缀、连字符还是下划线、`flash` 和 `Flash`、有没有 `-d` 这种变体，差一个字符就是 `model not found`。所以整理这份表的时候，我按控制台里实际显示的字符串抄，不做规范化改写。

下面是目前在 [Token173](https://token173.net)控制台模型列表里能看到的 ID，按家族分组。

## Claude 系

| 型号 ID | 一般用在什么任务 |
|---|---|
| `claude-opus-5-5` | 跨文件重构、架构判断、复杂调试、长链推理 |
| `claude-opus-4-8` | 上一代重型任务的对照组，老项目里还有在跑的 |
| `claude-sonnet-5-5` | 日常编码、单文件修改、常规分析，性价比档 |
| `claude-haiku-5-5` | 摘要、格式化、分类、Agent 里的小型后台请求 |
| `claude-fable-5` | 长文写作、风格类生成，适合做 A/B 对照 |
| `claude-fable-5-1` | 同上，小版本差异建议自己拿固定样本比 |

Claude 系用在代码和长文场景，输入侧往往远大于输出侧，缓存命中率对账单的影响比单价大。配置 Claude Code 时记得把 `ANTHROPIC_DEFAULT_HAIKU_MODEL` 和 `ANTHROPIC_DEFAULT_SONNET_MODEL` 一并指向这两个 ID，否则后台小任务会去撞一个不存在的默认型号。

## GPT 系

| 型号 ID | 一般用在什么任务 |
|---|---|
| `gpt-6.1-sol` | 复杂 Agent 规划、多步工具调用 |
| `gpt-6-sol` | 同上档位，做同族对照 |
| `gpt-6-astra` | 重推理、长文档分析 |
| `gpt-5.6-sol` | 中高档日常任务 |
| `gpt-5.6-terra` | 常规对话、客服、批量生成 |
| `gpt-5.5` | 稳定档，老业务迁移时常用 |
| `gpt-5.4` | 成本敏感场景的对照基线 |

实际项目里我按轻 / 中 / 重三档绑 ID，写成环境变量，不硬编码进业务代码。分档这一件事，通常比换平台省得多。

## Gemini / Grok

| 型号 ID | 说明 |
|---|---|
| `gemini-3.8-flash` | 高频、大批量、延迟敏感；长上下文和图片初筛常用这一档 |
| `grok-4.7` | 风格类生成、对照实验 |
| `grok-4.5` | 上一代对照，成本敏感时可留着跑 A/B |

Gemini 原生协议和 OpenAI 兼容格式差别比较大，聚合平台一般做了翻译层，接之前先测纯文本、图片输入、工具调用、流式四种请求，别只看「能返回」。

## 图像 / 视频

| 型号 ID | 说明 |
|---|---|
| `gpt-image-2` | 图像生成，通常走 `/v1/images/generations` |
| `gpt-image-2-d` | 变体，具体能力以控制台说明为准 |
| `doubao-seedance-2-0-fast-260128` | 视频生成，异步提交 + 轮询，ID 带日期后缀 |
| `sd-2-5-480p` | 480p 档视频 / 图像任务 |

带 `-260128` 这种日期后缀的 ID 最容易被手打错，建议一律从 `/v1/models` 返回里复制。视频类任务和文本不是一个计费逻辑，多按次或按时长计，别拿文本模型的每百万 token 单价去估。

## 国产线

| 型号 ID | 说明 |
|---|---|
| `deepseek-v4` | 通用推理，成本敏感场景的主力 |
| `deepseek-v4-pro-0813` | 加强档，带日期后缀 |
| `deepseek-v4-flash-0731` | 快速档，批量分类 / 抽取 |
| `glm-5.3-flash` | 轻量高吞吐 |
| `kimi-k3` | 长上下文、材料整理 |

国产线适合放在降级链的前段：便宜档先跑，遇到置信度低或任务复杂的样本再升档到海外型号。同一套代码里换 model 字符串就行，不用改鉴权和地址。

## 怎么确认自己这边可用

别信任何一篇教程里的列表，包括这篇。平台会上下架型号、调整分组和倍率，最可靠的做法是每次上线前拉一次：

```bash
curl -sS "https://token173.net/v1/models" \
  -H "Authorization: Bearer $RELAY_API_KEY" \
  | python3 -c "import sys,json; print('\n'.join(m['id'] for m in json.load(sys.stdin)['data']))"
```

把输出和实际配置做一次 diff，型号下架能提前发现。我们把它固化进部署脚本了，比人工核对省事。

再跑一组最小验证，确认这个 ID 在你要用的能力上没问题：

```python
from openai import OpenAI
client = OpenAI(api_key="...", base_url="https://token173.net/v1")

r = client.chat.completions.create(
    model="gpt-6.1-sol",
    messages=[{"role": "user", "content": "只回复 OK"}],
    stream=True,
    stream_options={"include_usage": True},
)
for chunk in r:
    ...
```

重点看四样：能否流式、能否工具调用、超长输入会不会被截断、`usage` 字段是否完整。有的型号能聊天但不支持 tool calling，Agent 场景一上就露馅。

## 关于命名，几句提醒

聚合平台的模型 ID 是平台自己维护的别名，不必然等于厂商官方文档里的版本号。同一个能力在不同站可能叫不同名字，也可能同一个名字对应不同分组和倍率。所以迁移平台时别只做字符串替换，要重新跑一遍上面的验证组。

另外，同一家族里 `-sol`、`-terra`、`-astra` 这类后缀代表不同档位，具体能力和计价以控制台模型说明与价格页为准。别凭名字猜哪个更强，拿自己业务的真实样本跑 30 条，比猜准得多。

## 最后

这份表是拿来对照用的，不是永久清单。型号会更新，价格会调，能力支持范围也会变。真要接进生产，把 `/v1/models` 的返回值当成唯一事实来源，其他都是参考。
