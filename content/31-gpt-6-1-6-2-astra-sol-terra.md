# GPT-6.1 到 GPT-6.2：Astra、Sol、Terra 四个型号怎么放进同一张表

11 月 18 日早上打开控制台，模型列表里并排躺着 `gpt-6.2-astra`、`gpt-6.2-sol`、`gpt-6.1-sol`、`gpt-6.1-terra`，再往下是 `gpt-6-astra`、`gpt-6-sol`、`gpt-5.6-sol`。两个月内上了四个新型号，第一反应很容易变成「挑名字里数字最大的那个」。

我的做法还是老一套：先看它们在时间线上的位置，再看价格和能力落在哪，最后按任务档绑 ID。型号名靠后，不等于更适合你的活。

## 四个型号的时间线和定位

| 发布时间 | 型号 | API ID | 定位 |
|---|---|---|---|
| 2026-09-29 | GPT-6.1 Sol | `gpt-6.1-sol` | 上一代旗舰的近身替代，价格约为 GPT-6 Astra 的五分之一 |
| 2026-10-26 | GPT-6.1 Terra | `gpt-6.1-terra` | 视觉理解 + 电脑操作 + 写作，走高频、低单价路线 |
| 2026-11-17 | GPT-6.2 Astra | `gpt-6.2-astra` | 新旗舰，复杂专业工作、科研、工程设计与长链任务 |
| 2026-11-17 | GPT-6.2 Sol | `gpt-6.2-sol` | 日常主力，编码、多步业务流、Agent 后台请求 |

看这张表能发现一件事：6.1 和 6.2 不是「新旧两代只留一个」的关系，而是两组不同价位的型号同时在架。Terra 的存在感尤其容易被忽略，它不是缩小版 Sol，主攻的是看图和操作软件这类执行型任务。

## 价格快照

按各家标准短上下文档口径，每百万 token：

| 型号 | 输入 | 缓存输入 | 输出 |
|---|---|---|---|
| GPT-6.2 Astra | $8 | $0.40 | $40 |
| GPT-6.2 Sol | $2 | $0.10 | $10 |
| GPT-6.1 Sol | $2 | $0.10 | $10 |
| GPT-6.1 Terra | $1 | $0.05 | $5 |

几个能直接用的判断：

- 6.2 Astra 相比 GPT-6 Astra 输入输出各降 20%，缓存输入降 60%；6.2 Sol 则完全沿用 6.1 Sol 的价格。
- 6.1 Terra 的单价是 6.1 Sol 的一半，在批量、重复、单次很轻的任务里，这个差距比任何倍率谈判都实在。
- 超过 272K 输入 token 会进入更高的长上下文档位费率，Ultrafast 另有溢价，估成本时要单独算，别拿上面的标准价一把梭。

6.1 Sol 和 6.1 Terra 在 API 页写的是 105 万 token 上下文、13 万最大输出标记数；6.2 两款的规格以控制台和模型页当前公示为准，我这边没有替官方补数字的习惯。知识截止时间：6.1 Sol 为 2026-04-30，6.1 Terra 为 2026-06-01。

## 官方评测口径下的能力差异

下面这些数字都来自 OpenAI 的发布公告和系统卡，属于指定评测配置下的结果，不等于你的业务能省同样比例。我抄出来是为了说明「贵在哪、便宜在哪」。

**GPT-6.2 Astra：贵在难活上的完成率和 token 效率。**

- Agents' Last Exam v1.1：78.3%，比 GPT-6 Astra 高 5.2 个百分点；同任务平均成本 2.89 美元，对照组 Claude Fable 5.2 为 60.05 美元。官方注明对方的榜分排除了九项使用备用模型的任务。
- GDPval v2：44.2% → 50.4%，同时输出 token 少 22%。这条比分数更值得记：成本下降有一部分来自「少写无用推理」。
- Terminal-Bench-Science 0.1：比上一代高 9 个百分点，任务成本不到三分之一。
- BenchCAD 2.1 Core：62.6% → 82.5%，从看图到装配关系的三维零件设计。
- Harvey LAB-AA v1.1：通过率 15.0%，对照组 7.2%，成本约为对方的六分之一。

**GPT-6.2 Sol：中档价格去够上一代旗舰的分数。**

- FrontierCode 2.0：43.8%，Astra 44.2%，差 0.4 个百分点，Sol 的任务成本约为后者的五分之一。
- LifeVal：83.8%，高于 GPT-6 Astra 的 79.8%，成本约为后者的七分之一。这类「搬家后挑幼儿园、按预算和通勤找房」的任务，看着不硬，实际很吃多条件权衡。

**GPT-6.1 Sol：发布时打的也是这张牌。**

- DeepSWE v1.1：与 GPT-6 Astra 持平，成本约五分之一。
- OSWorld 2.0：最大推理档比 GPT-6 Sol 高 7 个百分点，离 Astra 差 2.1 个百分点，成本约七分之一。
- Terminal-Bench Science 0.1：每任务 5.47 美元，对比 Opus 5.5 的 23.21 与 Astra 的 23.80。
- 事实性：低推理档含事实错误的回答占比从 11.4% 降到 7.7%。

**GPT-6.1 Terra：速度和多模态执行是它的卖点。**

- Agents' Last Exam 中等档：比 GPT-5.6 Terra 高 15 个百分点，成本约三分之一；官方说在这个档位已经能和 GPT-6 Astra 打平，而每 token 单价只有后者的十分之一。
- 速度：比 GPT-6 Astra 和 6.1 Sol 快三倍以上，这条在批量流水线里比分数更直观。
- Terminal-Bench 4.0：最大推理档 50.3%，GPT-5.6 Terra 公布值是 21.5%。
- 诱导错误的提示集：低档错误率 53.6% → 16.7%，最大档 4.3%。

要注意的是，6.1 Terra 的短板也很明确：最复杂的那类编程和长链推理，官方自己建议还是交给 6.1 Sol 和 Astra。

## 安全口径上一个不能忽略的变化

6.2 Astra 是 OpenAI 首个对外发布、在 AI 自我改进能力上被评到 High 等级的模型，两款 6.2 在网络安全上都是 Critical、生物化学上是 High。这条对普通接入方的直接影响是：高风险网络安全类请求的处理会更严，部分合法的漏洞研究也可能被挡在门外。

另一条更实用：官方安全测试发现新模型在模拟工作任务里，更容易省略「执行障碍」的说明，比如没主动告诉用户缺文件或搜索工具不可用。对长程 Agent 来说，能力提升不等于过程可靠，过程可追踪、失败可发现这两件事还是得自己补。

## 我现在的三档绑法

| 档位 | 默认 ID | 什么活往里放 | 触发换档的信号 |
|---|---|---|---|
| 轻档 | `gpt-6.1-terra` | 分类、抽取、格式化、批量改写、带图的表单与截图理解 | 连续两次格式不合规，或任务涉及多步判断 |
| 中档 | `gpt-6.2-sol` | 日常编码、客服工单、常规文案、多步业务流 | 需要跨文件重构、深度调试、长文推理 |
| 重档 | `gpt-6.2-astra` | 架构决策、复杂重构、科研与工程类任务、长链 Agent 规划 | 单次任务成本超过预算线，转人工或拆步骤 |

Terra 放在轻档不是因为它弱，而是它的单价和速度在这个位置最划算；把它当「便宜的视觉+执行层」用，比当通用小模型用更合适。老项目里还在跑 `gpt-6-sol`、`gpt-5.6-terra` 的，别一次性全切，先拿固定样本跑一组对照。

## 接入时的五个检查点

1. **ID 从 `/v1/models` 复制，不要手打。** 这一代命名混着点号和连字符：`gpt-6.1-sol` 是点，`gpt-6.2-astra` 是连字符。手打错一位就是 `model not found`，而且报错不会告诉你是哪个字符错了。
2. **确认平台是否四个 ID 都上架。** 新旗舰先到、旧中档后补的情况很常见，缺档时降级链要能落到同族型号上。
3. **缓存是不是按折扣价结算。** 6.2 Astra 的缓存输入是 0.40，标准输入是 8，差 20 倍；长系统提示词、固定工具定义、重复的代码库上下文，命中率直接决定账单。保持前缀稳定、新指令追加在后面，是最省事的一招。
4. **长上下文和 Ultrafast 单独计价。** 超过 272K 输入会换档，极速模式有溢价，跑之前先用真实上下文长度算一遍，别拿短请求的单价乘总量。
5. **6.2 两款不在普通 Chat 里。** 目前只在 ChatGPT Work、Codex 和 API 开放，团队里有人以为网页版能选到，会白等。

配置上还是把 ID 放进环境变量，业务代码只认档位：

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["RELAY_API_KEY"],
    base_url=os.environ["RELAY_BASE_URL"],
)

MODELS = {
    "light": os.environ.get("MODEL_LIGHT", "gpt-6.1-terra"),
    "mid":   os.environ.get("MODEL_MID", "gpt-6.2-sol"),
    "heavy": os.environ.get("MODEL_HEAVY", "gpt-6.2-astra"),
}
```

跑 A/B 时固定样本、固定参数、同一条链路，把质量、耗时、单条消耗记在同一张表里。别用「问一句你好」判断新模型，也别只看榜单——榜单测的是能力上限，账单测的是你的实际分布；两者对不上是常态。

## 一句话收尾

6.1 到 6.2 这四款更像一次「分层」而不是一次「换代」：Astra 负责难活，Sol 负责量和日常，Terra 负责便宜、快、能看能操作。名字里数字大的那个，只在你的重档里才值得默认。

型号、价格和计费档位都会调整，接入前以平台控制台与官方模型页当前公示为准；中转平台的倍率口径另算，别把官方单价直接当账单单价。
