# API 中转站的「倍率」到底是什么意思

> 「API 中转站倍率是什么意思」「中转站 0.2 倍率」「token 扣费 怎么算」「2026 中转站 价格对比」——同一个模型，A 站写 0.2 倍率、B 站写官方 8 折、C 站写每百万 token 多少钱，三个数字基准不同，直接比一定误判。

同一个模型，A 站写 0.2 倍率，B 站写官方 8 折，C 站写每百万 token 多少钱。三个数字没法直接比，因为它们的基准不是一回事。这篇只讲口径，不推荐平台。

## 一次扣费中间隔了两层换算

大多数中转站的账是这么算的：

```
官方 API 标价（美元）
   × 中转站设定的兑换口径（1 美元标价 = 多少平台币）
   × 该模型的倍率
   = 用户实际扣减
```

第一层是官方标价折算：系统先算「如果这些请求走官方 API 要花多少钱」，得出一个以美元计的标价额度。

第二层是平台币兑换：有的站 1 美元标价兑 1 元平台币，有的兑 6.8 或 7。这一步已经改变了你感受到的价格，但界面上通常不显眼。

第三步才是倍率，按模型、按分组、按输入输出方向分别设系数。

只看「倍率 0.2」就下结论，是最常见的误判。必须同时知道兑换口径，两个数字缺一个，价格没有可比性。

还有个容易重复计算的坑：如果平台已经把倍率算进了每次扣费（后台显示的就是最终扣除额），就不要再乘一次。很多人算不对账，卡在这一步。

## 倍率不是一个数字，是一组数字

- **按方向**：输入倍率、输出倍率常常不同。生成类业务输出占比高，输出倍率的权重更大。
- **按模型**：旗舰型号和轻量型号各配一套。宣传里那句「低至 0.1 倍率」往往只覆盖少数几个型号。
- **按分组 / 渠道**：同一模型可能有多条上游线路，稳定通道倍率高，低价分组倍率低但可能限并发、限 RPM，甚至来源不同。
- **按时段**：部分平台夜间或活动期调倍率，有时效性。

所以问「这家倍率多少」意义不大，该问的是「我实际要用的这个模型、这个输入输出比例、走这个分组，综合单价是多少」。

## 用综合单价横比

拿自己业务的真实 token 分布代入：

```
综合单价 = 官方输入单价 × 输入倍率 × 输入占比
         + 官方输出单价 × 输出倍率 × 输出占比
         + 缓存部分（按平台规则另算）
```

对话类产品历史上下文越滚越长，输入占比可能到七八成；内容生成反过来。同一家平台对两类业务，算出来的排名可能完全颠倒。

再补四个必问项：

1. 失败请求计不计费？
2. 客户端超时后的重试算不算新请求？
3. 缓存命中是否按折扣价结算，`cache_read_tokens` 有没有单列？
4. 有没有最低计费单位、阶梯折扣、余额低时的并发限制？

批量任务里，这四项能把预估账单拉偏不少。

## 倍率很低，成本从哪来

不是所有低价都有问题，但低到背离算力成本时值得多问一句。常见的几类来源：批量采购或协议价拿到的折扣、订阅制与按量 API 之间的价差、区域定价差异、上游企业账号的额度拆分，以及来源说不清的号池和逆向通道。

前几类能持续，后几类随时可能断。判断方法很朴素：让平台把上游类型、分组说明、倍率和兑换口径一起写清楚。写不清楚的，低价只是把风险换了个位置。

## 对账怎么落

选平台时优先看能不能给出请求级 usage，字段至少拆到 `prompt_tokens`、`completion_tokens`、缓存相关项。拿到一条具体请求，把完整 messages（含 system、历史、工具 schema）序列化后本地用对应 tokenizer 估一遍，和后台数字比量级。差 5%–10% 属正常波动，差 20% 以上再往深查。

我一般从 [token173.net](https://token173.net) 后台按 request_id 导单条明细来跑这个比对 —— 不是说它算得比别家准，而是字段拆得开、能导出，冷热各十条的成本差异能直接并排看。换成一个只显示「余额 -0.37」的后台，下面这四步一步都做不了，只能靠猜。

差距集中在缓存字段，多半是协议口径问题（Anthropic 的 `input_tokens` 只算未命中缓存的新增输入，OpenAI 的 `prompt_tokens` 是含缓存的总输入），不是扣错钱。差距集中在输入侧、且系统性持续出现，才需要怀疑灌水。

连原始 usage 都不给、只回一句「以账单为准」的，账是没法对的。这一项在 2026 年已经成了选型的分水岭：能不能对账，比便宜几折更影响长期成本。

## 一句补充

倍率作用于计费金额，通常不改变实际 token 消耗量——消耗多少由分词器和请求内容决定。少数平台把倍率直接乘在 token 数上再按统一单价结算，账面看起来 token 变多了，本质还是计费权重调整。

选型时把倍率和模型范围、通道质量、限流策略、账务透明度一起看。单独一个漂亮数字，说明不了什么。

（本文只讲口径。具体某家的倍率、兑换比例、价格请以各自价格页当前公示为准，这个行业调价很频繁。）

## 搜「倍率」的人，实际在问四件事

把搜索框里的问法归一下，指向的证据完全不同：

| 问法 | 真正想问的 | 该看什么 |
|---|---|---|
| 「0.2 倍率便宜吗」 | 跟别家怎么比 | 兑换口径 + 输入/输出/缓存分项 |
| 「为什么比官方便宜这么多」 | 上游来源正不正当 | 渠道说明、分组规则、可持续性 |
| 「余额掉得比预期快」 | 是不是被多扣 | 单条 request_id 的原始 usage |
| 「无限 token 套餐靠谱吗」 | 有没有隐藏上限 | 频次、并发、静默降速条款 |

第二行在 2026 年尤其值得展开。公开报道里把低价来源拆得比较清楚：批量采购或协议价、订阅制与按量 API 的价差、区域定价差异，属于能持续的；账号池轮换、逆向其他产品客户端、退款时间差这类，随时可能中断。前者能写进说明，后者只会写「渠道优势」。

所以判断方法还是那句：让平台把上游类型、分组说明、倍率和兑换口径一起写清楚。写不清楚的，低价只是把风险换了个位置。
